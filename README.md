# Ivan

AI native 的选股策略回测与向前跟踪（A 股 + 港股），可自部署。

用自然语言描述选股思路 → AI 把它翻译成结构化策略（你在卡片上确认才生效）→ 引擎在点时正确的历史数据上回测 →
满意后上线，每个交易日收盘后按规则重放一遍模拟盘，首页看板把回测与真实表现放在同一条曲线上对照。

> 仅供研究，不构成投资建议。数据来自第三方公开接口，可能有误差与延迟；请自行确认使用合规。

## 原则

- **LLM 负责翻译和解说，引擎负责算数。** 界面上的数字都来自引擎与数据库，卡片直接渲染工具结果。
- **只有规则能回测。** 让模型站在历史时点「挑股票」等于偷看答案（训练数据里有未来）。
- **点时正确。** 财报按公告日生效；A 股股票池含退市股；估值（市值、PE、PB）由当日股本与已公告财报自算。
- **诚实。** 样本外衰减、收益集中、交易太少、参数脆弱……由引擎按固定阈值算出并主动提示。

## 架构

```
apps/server   Hono：鉴权（better-auth + 邀请码）、REST、对话 Agent（AI SDK）、托管前端
apps/worker   调度（北京时间）+ ETL + 回测/扫描/跟踪/简报任务；行情仓 DuckDB 的唯一持有者
apps/web      Vite + React：看板、策略、回测报告、对话抽屉、管理页
packages/core     策略 DSL（zod）、因子注册表、市场规则与费率、类型
packages/engine   回测/跟踪模拟器、指标、归因、诚实检查（纯函数）
packages/data     数据源（东财、腾讯、交易所、中证、外汇中心）、行情仓、ETL、选股 SQL
packages/db       应用库 schema（SQLite + Drizzle）
packages/ai       LLM provider 配置（对话与夜间简报共用）
```

## 自部署

需要 Node 22+、pnpm 10+，以及一个 OpenAI 兼容（默认 DeepSeek）或 Anthropic 的 API key。除此之外不需要任何外部服务：
应用库是 `data/app.sqlite`，行情仓是 `data/market.duckdb`。

```bash
pnpm install
cp .env.example .env        # 至少改 BETTER_AUTH_SECRET、INTERNAL_SECRET、PUBLIC_URL、LLM_API_KEY
pnpm build                  # 构建前端
```

### 首次回填行情仓

回填是一次性的，**可断点续跑**（中断后重跑同一条命令即可）。worker 运行时会独占行情仓，回填要在 worker 停掉时跑。

```bash
pnpm ivan probe                         # 先确认数据源可达（只读，串行 0.6 秒一次，约一两分钟）
pnpm ivan backfill --market A           # A 股，2013 年起
pnpm ivan backfill --market HK          # 港股
pnpm ivan doctor                        # 看各表规模与最新日期
```

两家日 K 接口（东财 push2his、腾讯 fqkline）都有反爬：请求太密会被按 IP 暂时封禁（实测几十分钟到数小时）。
回填默认串行、0.6 秒以上一次，被封时自动暂停、换另一家、等解封后继续——全量 A 股 + 港股大约 2–4 小时，建议放到晚上跑。
数据源按封禁风险排成回退链（东财在前、腾讯在后，见 `.env.example` 的 `IVAN_CHAIN_*`，只能重排不能增删）；
某家把你的 IP 封了，可以用 `KLINE_SOURCE=tencent`（或 `eastmoney`）指定日线与指数只走一家、不回退。
每晚各来源服务了多少只、回退了几次，管理页的数据卡上看得到。
只想先试用，可以只回填市值最大的一部分：`pnpm ivan backfill --market A --top 300 --since 2016-01-01`。
这样的库，夜间增量只更新已经回填过的股票（外加近 30 天的新股），不会替其余股票补历史；要补就再跑一次不带 `--top` 的回填。

收盘价定稿前（北京时间 A 股 15:30、港股 16:30 之前）回填只取到昨天，手动触发的夜间增量会直接报错——
否则盘中价会被当成收盘价写进库。

### 升级已有的行情仓

新版本有时要给大表加列（比如约 2500 万行的日线、约 1600 万行的因子表）。worker 启动时不做这种升级，而是进入**维护状态**：
照常起来，但不排任务，看板写「行情仓维护中」。这时先停 worker、跑一次 `pnpm ivan migrate`（一次升到当前版本），再拉起 worker；
用 pm2 部署的可以直接 `bash scripts/migrate.sh`（会先备份行情仓）。开发机图省事可以在 `.env` 里设 `WAREHOUSE_MIGRATE_ON_BOOT=1`，
worker 启动时直接升级。

### 运行

```bash
pnpm start                                # 最简：同时拉起 server 与 worker
# 或者用 pm2（推荐，崩溃自动重启）：
pm2 start ecosystem.config.cjs && pm2 save
```

打开 `PUBLIC_URL`，**第一个注册的账号自动成为管理员**，之后注册需要邀请码（管理页生成，或 `pnpm admin invite`）。

夜间任务（工作日，北京时间）：17:30 更新 A 股并结算 A 股跟踪、18:00 港股、19:00 生成简报，周日 03:00 抽检历史日线。
管理页可以手动触发。每晚的顺序是：指数与日历 → 证券表 → 日线 → **完整性闸门** → 简称、财报与股本 → 因子 → 结算（spec D73）。
闸门在财报与因子之前：缺日线的股票超过 A 股 max(3, 0.2%)、港股 max(5, 0.3%)，或今天没成交的股票远多于平时，
就停在这里、不算今天的因子（回测与结算仍读前一个交易日的数据），45 分钟后自动重跑，最多 2 次；
「开市了但指数日 K 还没有今天」也一样自动重跑。等重跑期间首页横幅写明原因和几点重试，简报与跟踪判词说「数据没更新」，不会说成休市。
缺的只是运行中跟踪的持仓或明日计划里的股票时不让整晚失败，只让这些跟踪显示「数据未更新」。
写入日线前先体检：价格关系不对、成交量为负、日期不是交易日的日线不入库，其余异常（超过涨跌幅、复权因子无故跳变等）只标记，
都列在管理页「数据质量」卡，可以逐条「标为已核对」；之后重新拉到干净的数据、或每周抽检比对一致时自动关掉。
汇率、证券表、简称、财报这类辅助数据失败时沿用旧数据、不让整晚失败，但每晚的结果都记下来：连续 3 晚失败时管理页出横幅，
财报与股本连续失败时回测与跟踪也带「财报与股本久未更新」提示。每次回测的复现信息里写着行情来源占比与缺失天数。
夜间更新写行情仓期间回测、扫描、复核排队等更新结束（等自动重跑的那 45 分钟里不用等）。
A 股每晚在财报之后、因子之前还同步四个点时事件数据集：两融明细（前两个交易日 + 近 20 个交易日里没到齐的日子）、
股东户数（公告日近 14 天）、限售解禁（解禁日前 7 天到后 180 天）、大宗交易（近 7 天），每行记下「公布后哪天才可得」；
每个数据集先跑一次接口自检（字段与单位），没通过就当晚不删不写、整晚照常，管理页「两融与筹码数据」写明原因。
一晚约 30–40 次请求、半分钟左右；周日的抽检再补扫一次更宽的窗口，补上东财晚入库的行。
历史在管理页「补齐历史数据」后台分段补齐（约 1.7–1.9 万次请求，每段最多 10 分钟，16:30–21:00 暂停），不停服务、不影响回测。
这些数据变成 7 个只适用于 A 股的「两融与筹码」因子（融资余额占流通市值、融资余额 20 日变化、两融标的、股东户数环比、
距下次解禁、30 天内解禁占流通股、大宗交易折溢价），可以当筛选条件和排序项；都按公布后可得的日期算，数据过期就为空，
没有已知解禁时距下次解禁记为 181 天（所以「距下次解禁 > 90 天」不会把没有解禁的股票排除）。
新因子不重算已有因子：夜间和别的因子一起算近 15 天，历史在补齐完成后由 worker 按年补算（每次一年，16:30–21:00 不补，
管理页写「事件因子：补算中（7 / 14 年）」）；补完之前用到它们的回测会被拒绝，今天的选股可以先用；不用它们的旧回测、旧跟踪逐字节不变。
对话里问个股的融资余额、户数、解禁、大宗交易会出一张「两融与筹码」卡，个股证据也多了这一组。
简报只在当天确实有新行情时才说「今天」涨跌；休市日说休市，更新失败、还没跑完或在等重跑时说数据没更新、不会说成休市。
重跑成功时如果当天的简报已经写过，会再写一版；每一版都保留，不再按天数清理。

回测在单独的线程里跑：线程崩溃或超过 `BACKTEST_TIMEOUT_MS`（默认 120000 毫秒）会被终止并自动重建，
线程堆上限是 `BACKTEST_THREAD_MEMORY_MB`（默认 256）。小内存机器按 `.env.example` 里的内存预算配置
（jim-server 的取值见 [DEPLOY.md](DEPLOY.md)）。

每次回测都记一张运行卡（策略、区间、成交假设、引擎、数据版本、输入指纹、结果指纹），可以在回测页下载。
「复核数据」只重新组装输入、比输入指纹，计入每日「数据查询」额度（`QUOTA_ANALYSES`，默认 100）；
「完整重跑」照原参数再跑一遍、比成交与指标，计入回测额度，不算进试错次数。
跟踪锁定上线时基准回测的成交假设；每晚重放和上次不一致时，跟踪页写明原因（数据修订、引擎升级、成交假设变更、早于指纹记录或原因不明）。
新回测默认用规则表第 2 版（按日期的涨跌停与费率表：主板 ST 10%、注册制新股上市后前 5 个交易日不设涨跌幅、过户费与港股交易费历史等）
与指标第 2 版（从投入第一笔资金算起、胜率按完整持仓、补索提诺 / 信息比率 / VaR 等风险指标）；以前的回测与跟踪仍按旧口径，结果不变。
R2 起指纹口径升到 2，R1 记下的指纹会被当成「早于指纹记录」一次，属于预期。
第 2 版口径的新回测还会给出「可信度」：按历史日收益成段重抽样 1000 次的年化收益、超额、夏普、信息比率、最大回撤的 95% 区间，
跑赢基准的把握（PSR）与一年净值扇形；种子来自输入指纹，同样的输入第二天重跑区间也完全一样。这是区间，不是预测。
新回测默认**按流动性成交**：成交价加减单边滑点（A 股 5bp、港股 10bp）和半个最小价位，再计平方根冲击成本；单笔买入不超过
决策日 20 日均成交额的 10%，不知道成交额的股票不买。所以同一策略的新回测收益通常比以前低一些；旧回测不变。
回测页「成交与容量」分页列出滑点成本、被成交额上限截掉的单子与按资金规模估的容量，回测对话框里可以改这些设置。
回测与跟踪页的「证据」按钮（对话里问「为什么买了它」也一样）列出决策日当时的收盘价、因子、财报、数据状态与两融筹码，每项带出处与数据日。
对话回复里的数字会逐个和工具结果核对，找不到出处的数在回复下面标出来，请以卡片为准。
跟踪页与看板给每个跟踪一个判词（正常、偏离、可能失效、观察期、数据未更新、结算失败），按跑赢回测同期、回撤比等健康指标逐晚算出；
「可能失效」只建议复核规则，系统不会替你停止或卖出。
A 股策略的基准可选沪深300、中证500、中证1000、中证红利全收益（含分红）或上证指数；入选股票的市值排名中位数明显偏小、
或排序主要看股息率时，回测提示「基准可能不匹配」。港股策略可以勾「只选港股通标的」。
「调参次数」数同一个策略在重叠 ≥ 50% 的区间里试过的不同设置（含参数扫描、按策略内容去重），挪一天起点不会清零，新建策略从零算。
跟踪页「回溯」分页看决策记录：时间线（计划、修订、重放差异、状态变化、简报、上线、停止）、某晚第 1 版计划对最新版与按现在数据重放的执行结果、
5 / 20 个交易日后的表现；「校验」重算你的整条账本链，「导出（JSON）」下载可自行重算的文件（别的跟踪与简报只带哈希），
用 `pnpm admin verify-bundle` 离线校验。自部署实例上这证明的是「内部一致、改动能被发现」，不是第三方不可抵赖。

### 管理命令

```bash
pnpm admin users                              # 列出用户
pnpm admin invite 给朋友                        # 生成邀请码
pnpm admin reset-password 邮箱 新密码            # 忘记密码（v1 没有邮件服务）
pnpm admin set-role 邮箱 admin
pnpm admin verify-bundle ivan-trace-xxx.json   # 离线校验跟踪页「回溯」导出的决策记录（通过退出码 0，否则 1 并指出第几条）
pnpm ivan backtest strategy.json               # 命令行回测一份策略（调试用，worker 停掉时）
pnpm ivan screen strategy.json                 # 按策略在最新数据日选股
ETL_ACCEPT_MISSING=600000.SH pnpm ivan daily --market A   # 某只股票长期拿不到日线、拖得整晚失败时，应急放行（也可以写进 .env，worker 夜间任务同样认）
pnpm ivan events --market A --estimate          # 估算两融与筹码数据回填的请求数与时长（只发 4 个计数请求；worker 在跑时用管理页的「估算」）
pnpm ivan events --market A [--datasets margin,holders,lockups,blocks] [--since 2013-01-01] [--force]
                                                # 命令行直接回填事件数据（先停 worker；平时用管理页「补齐历史数据」）
pnpm ivan event-cols --market A [--force]       # 命令行按年补算事件因子列（先停 worker；平时回填完成后 worker 自动排）
bash scripts/migrate.sh --down 4                # 换回 R4 或更早的代码之前（在当前代码上跑）删掉 7 个事件因子列（见 DEPLOY.md）
```

## 已知局限

- 港股没有退市名单，港股回测有幸存者偏差（结果里常驻提示）。
- 港股财报没有公告日，按法定披露期限保守推算生效日（年报 +90 天，中报/季报 +60 天）。
- 2018 年以前的沪市股票与沪市退市股，ST 用「最近两期年报都亏损」近似判定。
- 行业用东财的当前行业分类，不是历史分类。
- 中证 500 / 1000 / 红利全收益基准取自中证官网（H00905 / H00852 / H00922），代码要用 `pnpm ivan probe` 核对；
  新加的指数第一次夜间更新时从 2013-01-01 拉全，某个基准的历史比回测起点晚时，提交回测就会被拒并给出它的首个数据日。
- 港股通股票池用每晚记下的名单按决策日筛选，名单从第一次记录那天起才是当时的名单，之前的日子用第一次记录的名单（回测里有提示）；
  目前只记深港通名单，沪港通的标记列核实后再加。
- 深市两融 T 日的数据要到下一个交易日才有，所以两融、大宗交易都按 T+1 才算「可得」；只拿到一个交易所的两融日子记为没到齐，之后的夜里重取。
- 限售解禁没有公告日：历史上的可得日按规则推算（首发按上市日，其他按解禁日前 3 个交易日），上线后以每晚首次见到的日子为准；
  用到解禁因子、起点早于每晚同步开始的回测带「解禁的可得日为推算」提示。
- 两融与筹码因子只有 A 股；数据集连续 3 晚没更新成功时相关因子按过期规则为空，回测与跟踪带「数据过期」提示。
- 已公告未除息的分红预案还没有接入。
- 数据来自非官方接口，接口变动时用 `pnpm ivan doctor` 排查。
