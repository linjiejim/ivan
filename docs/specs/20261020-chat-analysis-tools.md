## 背景

线上对话里用户问「腾讯上市以来涨了多少」「之前的逐日股价你没有吗」「港股指数的趋势」，模型只能回答「没有逐日行情接口」。
行情仓里其实有 2013 年起的 A 股、港股逐日行情、指数与全收益、点时因子与财报，只是对话工具只有 `lookup_security`（最新一期因子与几期财报），
没有任何读历史行情、做横向比较或算数的工具。模型又被要求「数字只能来自工具」，于是只能说没有。

## 设计

原则不变：**LLM 负责翻译和解说，引擎负责算数**。所有统计在 worker（`packages/data/src/query/analytics/`、`compute/price-stats.ts`）算好，
server 的工具只转发并给模型一份四舍五入过的精简摘要（也是数字核对的证据），卡片直接画完整结果。只读已提交的数据（D60）。

| 工具 | 内部接口 | 用途 |
| --- | --- | --- |
| `get_price_history` | `POST /internal/analytics/price-history` | 个股或指数任意区间：收益、年化、最大回撤（峰谷与修复日）、波动、最高最低、多窗口涨跌、均线位置、相对基准超额 / β / 相关、指数全收益、上市以来 |
| `compare_securities` | `POST /internal/analytics/compare` | 2–6 只股票或指数同区间对比 + 两两相关 + 关键因子 |
| `get_market_overview` | `POST /internal/analytics/market` | 大盘某天：指数、涨跌家数与分布、涨跌停、成交额 / 20 日均、新高新低、站上 60 日线、最强最弱行业、估值中位数与 5 年分位 |
| `get_industry_performance` | `POST /internal/analytics/industries` | 行业区间表现排行；给行业名时列成分股 |
| `get_factor_history` | `POST /internal/analytics/factor-history` | 个股因子历史（当前、最低最高、中位、分位）与当天全市场 / 同行分位 |
| `get_financials` | `POST /internal/analytics/financials` | 多期财报、单季与 TTM、分红送转与每年分红 |
| `calculate` | （server 本地） | 四则、乘方、% / 万 / 亿后缀、白名单函数（cagr、annualize、change…） |

## 决策记录

- **D99 走势的口径**：收益、回撤、波动按复权价（不复权收盘 × 等比复权因子，分红再投入）；价格与点位按不复权收盘。
  区间收益从「起点日当天或之前最后一个交易日」收盘算起（今年以来的起点是上年 12-31）；不足 365 个自然日不年化；波动按每年 250 个交易日。
  多窗口里历史不够的窗口为空，不拿更短的区间冒充。个股默认对比市场默认基准（全收益），指数默认不比、但并列同期全收益。
  「上市以来」只能从行情仓第一根 K 线算（发行价不在库里），第一根 K 线不是上市首日时明说。
- **D100 对比**：共同终点取各市场已提交截至日里最早的一天；A 股与港股混比时各按本币、不换汇，相关系数只用共同交易日。
- **D101 大盘宽度**：涨跌按复权（除权日不算下跌）；A 股涨跌停按收盘价是否等于涨跌停价（规则表第 2 版，除权日用参考价当前收），
  上市不满 10 个自然日的不算；新高新低按近 250 个交易日复权收盘、至少有 120 天行情；成交额缺失时用收盘 × 成交量估算；
  估值分位取近 5 年每周五（加当天）的全市场中位数，说明股票池逐年扩容、和指数估值不是一回事。
- **D102 行业**：行业归属按终点当天的点时属性；行业收益按起点总市值加权（另给中位数与上涨比例）；是行情仓里的股票自己算的，不是官方行业指数。
- **D103 因子历史与财报**：PE、PB、PEG 的历史与横截面只算正值；单季 = 本期累计 − 同年上一期累计（缺一期就不拆），港股拆成 H1 / H2；
  TTM = 本期累计 + 上年年报 − 上年同期；财报取每个报告期最新的一版。
- **D104 数字核对第 3 版**：价格键（close、highClose、firstOpen、dealPrice……）按金额归类；对象里写了 unit 时同一对象的其他数值按它归类
  （样本数、计数除外）；「24211 点」（≥ 100）按普通数核对；负数的方向词可以跟在数字后面（「还有 37.2% 的回撤」）。
- **D105 计算器**：模型要换算、相减、算金额时必须调用它（提示词硬性规则 1）；不 eval，只认数字、四则、乘方、括号、% / 万 / 亿后缀与白名单函数；
  函数表用 Map（`constructor` 这类名字查不到原型链）；unit 为 % 时把比例显示成百分数。模型摘要里不带表达式，免得模型写进表达式的数被当成证据。
- **D106 提示词、步数与额度**：分析类问题允许最多 300 字、5 条列表，先结论后依据，说清数据截至与口径，不预测、不给买卖点；
  明确列出数据范围（没有美股、分钟线、新闻、发行价）。单轮步数 8 → 12。6 个行情工具各计 1 次「数据查询」（D59，拿到结果才扣），计算器不计。
  当天该市场更新失败（D78 的 stale）时，结果的 notes 第一条写「数据没更新」。
- **D107 结果类型放进 `@ivan/core`**：worker 计算、server 摘要、web 卡片三处共用一份形状（`packages/core/src/analytics.ts`），不再各自声明。
