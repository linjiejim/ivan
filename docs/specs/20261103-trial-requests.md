# 试用申请：没有邀请码的人留邮箱，管理员一键发邀请

- 状态：draft
- 创建：2026-11-03
- 相关：MVP spec §10 账号与额度、D11 邀请码注册

## 背景

演示站开放试用以后，注册要邀请码，但陌生访客不知道去哪要：博客项目页只能写「分批发放」，
直接打开演示站的人在登录页也只看到「用邀请码注册」。要一个入口让人申请，申请要能及时到管理员手里，发码要省事。

## 方案

- **入口在登录页**：`/apply` 公开页，登录页和注册页的邀请码提示里都链过去。表单三项：邮箱（必填）、怎么称呼、想用 Ivan 看什么。
  博客项目页的「申请邀请码」按钮也指向这里，从博客来的和直接打开演示站的走同一个入口。
- **先落库，再提醒**：申请写进应用库 `trial_requests`，然后（配了发信时）给 `TRIAL_NOTIFY_TO` 发一封提醒，回复地址是申请人，
  直接回复就是回复对方。提醒发不出去不影响收下申请，原因记在这条申请上、管理页标出来。
- **管理页一键处理**：「试用申请」卡片列出待处理的申请，「发邀请」生成 14 天有效的一次性邀请码（备注记申请人邮箱），
  配了能发到外部地址的发件域名就把注册链接直接发到申请人邮箱；发不出去就给出链接让管理员复制自己发。「忽略」只改状态。
- **防滥用**：接口公开，每个 IP 每小时最多 3 次（内存里）、全站 24 小时最多 30 条（库里），蜜罐字段挡脚本；
  同一邮箱已有待处理的申请时不重复记录、不重复提醒。
- **默认关闭**：自部署的实例要设 `TRIAL_REQUESTS_ENABLED=true` 才有这个入口；没开时 `/apply` 说明「没有开放申请」，接口 404。

## 决策记录

- **D109 试用申请走自己的库和 Resend 的 HTTP 接口（2026-11-03）。** 申请记在应用库而不是只发一封邮件：邮件丢了、发信没配好，
  申请也还在管理页上，发邀请时能把邀请码和申请对上。发信只用 Resend 的 HTTP 接口（一次 `fetch`），不引入 SMTP 依赖；
  没配 key 就不发信，其余照常。用 Resend 的测试发件地址时只能发给 Resend 账号本人，够用来提醒管理员；
  要把邀请发到申请人邮箱得验证自己的域名，这一步交给部署者，代码里发不出去就退回「复制链接自己发」。
  不做自动发码：谁能用由管理员看过申请再决定，演示站的模型额度是真金白银。

## 验收标准

1. 不登录能在 `/apply` 提交申请；登录页、注册页在开放时显示入口，关闭时不显示。
2. 申请先落库再提醒；提醒发不出去也收下，并在管理页标出。
3. 同一 IP 一小时第 4 次被拒；同一邮箱排队中不重复记录；蜜罐提交不落库。
4. 管理员「发邀请」后申请人收到能用的注册链接；同一条申请不能处理两次；普通用户看不到也处理不了申请。
