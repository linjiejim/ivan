# Ivan MVP：AI native 的选股策略回测与向前跟踪

- **日期**：2026-09-28
- **状态**：confirmed
- **依赖**：无（全新项目，与 Iva 完全独立，不共享代码与数据）
- **范围**：
  - 做：TS monorepo 脚手架；A 股 + 港股行情/财务数据仓（东财 + 腾讯免费接口）；策略 DSL；回测引擎；
    向前跟踪（模拟盘）；对话 Agent（生成式卡片）；首页看板；夜间调度 + AI 简报；
    邀请码账号体系 + 每用户额度；演示站部署与自部署说明。
  - 不做：Tushare Pro（只留 adapter 接口）；实盘下单/券商对接；A+H 混合策略；
    AI 判断型策略（LLM 每日自主选股）；分钟/日内数据；指数成分股历史池；策略分享/社区；
    移动端 App；Docker 镜像发布；英文界面；开源许可证选择（公开前再定）。

## 背景与目标

Iva 验证了「规则化选股 + 回测 + 向前跟踪 + 看板对照」这条路有用，但它绑在 Hermes + 飞书上：
只服务 Jim 一个人，策略写死在 Python 里，改一条规则得改代码。

Ivan 要做成一个**开源、可自部署**的 Web 应用：任何人用自然语言描述选股策略，
AI 把描述翻译成结构化策略，引擎在 A 股或港股历史数据上回测，满意后「上线」按日向前跟踪。
首页看板汇总回测和跟踪的关键结果。Jim 会在自己的服务器上部署一份给朋友用。

### 设计原则

1. **LLM 负责翻译和解说，引擎负责算数。** 界面上的每个数字都来自引擎或数据库。
   卡片直接渲染工具输出，LLM 不转述数字，只写解读。
2. **只有规则能回测。** LLM 的训练数据里有「未来」，让它站在历史时点选股等于偷看答案。
   v1 只支持规则策略和信号导入这两种策略。
3. **点时正确（point-in-time）。** 财报按公告日生效，股票池包含已退市的股票，不用未来数据。
   数据做不到时，在结果里明确标出偏差，不假装没有。
4. **可复现。** 一次回测 = 策略版本 + 数据版本 + 引擎版本，三者相同则结果逐笔一致。
5. **诚实。** 过拟合、集中度、交易过少这类问题由引擎确定性地算出来，主动提示，不等用户问。
6. **自部署零外部依赖。** 除 LLM API 外不需要任何外部服务：SQLite + DuckDB 两个文件，
   Node 22 + pnpm 即可运行。

### 术语

| 术语 | 含义 |
|---|---|
| 策略 Strategy | 一个用户的一条选股思路，有名字、市场，下面挂多个版本 |
| 策略版本 StrategyVersion | 一份不可变的 `StrategySpec`；任何修改都产生新版本 |
| 草稿 Draft | LLM 提出的新建或修改方案，用户在卡片上点确认后才成为版本 |
| 回测 Run | 某个版本在某个区间、某个数据版本上的一次历史模拟 |
| 跟踪 Tracking | 某个版本从上线日起每日向前模拟；版本固定，不随策略修改 |
| 信号集 SignalDataset | 用户导入的（日期、代码）列表，用来只测买卖和仓位规则 |
| 因子 Factor | 注册表里的一个可用字段，如 `roe_ttm`；DSL 只能引用注册表里的因子 |
| 数据版本 DataVersion | 一次 ETL 成功后的行情仓版本号 + 截至日期 |

## 设计

### 1. 仓库结构与技术栈

沿用作者其他项目在自己服务器上跑过的栈（Hono + Vite React + Drizzle + pm2），
工程规范同样沿用（pnpm workspace + catalog、turbo、根目录统一 eslint/prettier、vitest）。

```
ivan/
├── apps/
│   ├── server/   Hono：鉴权、REST、对话 Agent、托管 web 构建产物（对外唯一端口）
│   ├── worker/   调度 + ETL + 任务执行（回测/扫描/跟踪/简报）；DuckDB 的唯一持有者
│   └── web/      Vite + React 19 + react-router + TanStack Query + Tailwind v4 + shadcn/ui + ECharts
├── packages/
│   ├── core/     领域类型、StrategySpec（zod）、因子注册表、市场规则与费率表、预设模板（纯 TS，无 IO）
│   ├── engine/   模拟器与指标、诚实检查（纯函数，输入面板数据、输出结果）
│   ├── data/     MarketDataSource 接口 + eastmoney/tencent 实现 + 行情仓读写（DuckDB）
│   └── db/       应用库 schema（Drizzle + SQLite）与迁移
└── docs/specs/
```

- 运行时 Node 22（服务器上 nvm 的默认版本）。生产环境用 `tsx` 直接跑 TS（和作者的其他项目一样），web 由 Vite 构建。
- LLM 接入用 Vercel AI SDK（`ai` + `@ai-sdk/react` + `@ai-sdk/openai-compatible` / `@ai-sdk/anthropic`）。
- DuckDB 用 `@duckdb/node-api`；鉴权用 better-auth（email + password，admin 插件）。

### 2. 进程模型

```
浏览器 ──HTTPS──▶ Caddy ──▶ ivan-server (:PORT)
                              │  SQLite（WAL，读写）
                              │  内部 HTTP（127.0.0.1:WORKER_PORT，共享密钥）
                              ▼
                           ivan-worker ── DuckDB（唯一持有者）
                              ├─ 调度器（显式 Asia/Shanghai）
                              ├─ ETL（东财/腾讯，全局并发 4，退避重试）
                              └─ worker_threads 池（回测/扫描，默认大小 1）
```

- server 通过 worker 的内部接口提交任务，也用它做同步的行情查询（选股扫描、个股卡）。
  任务状态和进度写在 SQLite 的 `jobs` 表里，server 读这张表并通过 SSE 推给前端。
- worker 启动时把残留的 `running` 任务标记为 `failed`（原因写「worker 重启」），不自动重跑。
- 回测分两步：主线程用 DuckDB SQL 完成选股（阶段 1），再把选中股票的日线装进 TypedArray，
  转交给 worker_thread 模拟（阶段 2）。这样重计算留在 DuckDB 里，JS 堆上只放选中股票的数据。
- DuckDB 设置 `memory_limit=1GB`、`threads=2`，可配置。线上服务器只有约 4 GB 内存。

### 3. 数据仓

#### 3.1 数据源接口

```ts
// packages/data
interface MarketDataSource {
  id: 'eastmoney' | 'tushare';
  listSecurities(market: Market): Promise<Security[]>;          // 含已退市（能拿到的话）
  dailyBars(code: string, from: string, to: string): Promise<RawBar[]>;   // 不复权 + 复权因子
  financials(market: Market, reportDate: string): Promise<FinancialRow[]>; // 全市场某报告期
  dailyValuation(market: Market, tradeDate: string): Promise<ValuationRow[]>;
  indexBars(sym: IndexSym, from: string, to: string): Promise<IndexBar[]>;
  nameHistory?(code: string): Promise<NameSpan[]>;              // ST 判定用
}
```

v1 的实现 = 东财数据中心（`datacenter(-web).eastmoney.com` JSON 报表）+ 腾讯日 K
（`raw` 与 `hfq` 各拉一次，复权因子 = hfq / raw）。
**不用 `push2.eastmoney.com`**：部分网络环境下连不上。Tushare 二期按同一接口接入。

#### 3.2 表（DuckDB，`DATA_DIR/market.duckdb`）

| 表 | 主键 | 要点 |
|---|---|---|
| `securities` | code | market、name、board（main/gem/star/bse/hk）、list_date、delist_date、lot_size、industry |
| `name_history` | code, start | 历史简称，按日期判定是否 ST |
| `bars_daily` | code, date | open/high/low/close **不复权**、volume、amount、adj_factor、suspended |
| `financials` | code, report_date | notice_date、营收、归母净利、扣非净利（仅 A 股）、EPS、ROE、毛利率、负债率、经营现金流 |
| `valuation_daily` | code, date | 总市值、PE_TTM、PB（A 股取源数据；港股按探针结论取源数据或自算） |
| `index_bars` | sym, date | 沪深300、上证、恒指、国企指数（全收益版本按探针结论） |
| `trade_calendar` | market, date | 由指数日线推出 |
| `factors_daily` | code, date | 物化的因子宽表，带 `registry_version` |
| `data_versions` | id | market、as_of（截至日）、finished_at、revised_rows（ETL 发现历史数据被修订的行数） |
| `etl_progress` | task, key | 回填断点，支持中断后续跑 |

- 日期一律存 `DATE` / `'YYYY-MM-DD'`，含义是交易所本地日期（A 股和港股都是 UTC+8），不存毫秒时间戳。
- 行业用东财的**当前**行业，拿不到行业的历史变更，这一点作为已知偏差写进文档。
- 回填：`pnpm ivan backfill --market A --since 2016-01-01`，可断点续跑，预计要几个小时（探针给出实测值）。
  → 探针后改为默认从 2013-01-01 回填，全量（A + 港股）实测估算约 2 小时，见 D18、D26。

#### 3.3 因子注册表（`packages/core/factors.ts`）

interface FactorDef {

|---|---|---|---|

| 估值 | `pe_rel_industry`（PE / 行业中位数）、`industry_mcap_rank` | ✅ | ✅ |
| 质量 | `roe_ttm`（本期 + 上年年报 − 上年同期）、`gross_margin` `debt_ratio` `ocf_to_profit` | ✅ | ✅ |
| 成长 | `rev_yoy` `np_yoy` `rev_cagr_2y` `np_cagr_2y` | ✅ | ✅ |
| 成长 | `deducted_np_yoy` | ✅ | ❌ 港股没有扣非口径 |
| 技术 | `chg_20d` `chg_60d` `chg_250d` `dist_high_60d` `dist_high_250d` `ma20_slope` `ma60_slope` `above_ma60` `vol_ratio_20d` `volatility_60d` | ✅ | ✅ |
| 分类 | `industry` `board` | ✅ 东财二级行业 | ✅ 东财港股行业 |
| 标记 | `flag_new_listing` `flag_loss` `flag_value_trap` `flag_low_base` `flag_high_debt` `flag_chasing` `flag_downtrend` | ✅ | ✅（价值陷阱用归母净利） |
| 标记 | `flag_st`（见 D21）`flag_deducted_decline` | ✅ | ❌ 港股无 ST/扣非 |

- 标记的判定逻辑参考 Iva 公开的口径，但在 TS 里重新实现，不复制代码。
- 因子只用 `notice_date ≤ 当日` 的财报计算。修改任何因子定义都要把 `registry_version` 加 1，
  worker 检测到版本变化后全量重算 `factors_daily`。

### 4. 策略 DSL（`packages/core/strategy.ts`，zod 校验）

```ts
type StrategySpec = {
  schema: 1;
  name: string;
  market: 'A' | 'HK';
  mode: 'rules' | 'signals';
  universe: {
    boards?: Board[];                             // A 股默认 ['main','gem','star']，不含北交所
    exclude: ('st' | 'new_listing' | 'loss' | 'suspended')[];
    minMcap?: number;                             // 亿，本币
    industries?: { include?: string[]; exclude?: string[] };
  };
  filters: Condition[];                           // 全部满足（AND）
  rank: { terms: { factor: string; weight: number; better: 'high' | 'low' }[]; top: number };
  rebalance: { every: 'week' | 'month' | 'quarter' };   // 每个周期的第一个交易日
  sizing: { method: 'equal'; maxWeight?: number };      // v1 只做等权
  exits: {
    takeProfit?: number;                          // 相对成本的收益率，如 0.3
    stopLoss?: number;                            // 如 0.15
    maxHoldDays?: number;                         // 交易日
    dropWhenFiltered?: boolean;                   // 调仓日不再满足 filters 就卖，默认 true
  };
  signals?: { datasetId: string };                // mode='signals' 时替代 universe/filters/rank
  costs?: { commission?: number; minCommission?: number };  // 覆盖默认佣金
  benchmark?: 'csi300' | 'sse' | 'hsi' | 'hscei'; // A 默认 csi300，HK 默认 hsi
};

type Condition =
  | { factor: string; op: '>' | '>=' | '<' | '<='; value: number }
  | { factor: string; op: 'between'; value: [number, number] }
  | { factor: string; op: 'is' | 'not' }                        // bool 因子
  | { factor: string; op: 'in' | 'not_in'; value: string[] };   // category 因子
```

- **排序**：每个 term 取该因子当日的横截面百分位（0–100，`better: 'low'` 时取反），
  按权重加权求和，取前 `top` 只。简单、可解释，能近似表达 Iva 那类加权打分公式。
- **编译成 SQL**：选股阶段由 `filters` + `rank` 编译成对 `factors_daily` 的查询。
  因子名只能来自注册表白名单，数值走参数绑定，没有注入面。
- **回测参数不属于策略**：`{ start, end, capital = 1_000_000, oosMonths = 12 }` 在发起回测时传入。
- **预设模板**（`core/presets.ts`）：低估值高 ROE 龙头、高股息、GARP 成长、中期动量，
  A 股和港股各有一套，新用户点一下就能建策略并回测。

### 5. 成交与市场规则（`packages/core/markets/{a,hk}.ts`）

- **时序**：T 日收盘后，用截至 T 日可得的数据做决策（选股、止盈止损判断），
  T+1 日按**开盘价（不复权）**成交，按整手取整
  （A 股 100 股；港股用 `securities.lot_size`，历史每手变化不建模）。
- **买不进和卖不出**：A 股 T+1 开盘价达到涨停价则不买，达到跌停价则不卖，卖单顺延到下一个交易日；
  停牌时不买，卖单顺延。涨跌幅按板块和日期生效
  （主板 10%、ST 5%、创业板 2020-08-24 起 20%、科创板 20%、北交所 30%）。港股没有涨跌停。
- **收益口径**：持仓按后复权计价，分红视为再投入同一只股票。
- **卖出后的现金**：闲置到下一个调仓日再用（见 D15）。
- **费率按日期生效**：

| 市场 | 佣金（默认，可覆盖） | 印花税 | 其他 |
|---|---|---|---|
| A | 万 2.5，最低 5 元 | 卖出 0.1%，2023-08-28 起 0.05% | 过户费 0.001% 双边 |
| HK | 万 3，最低 3 港元 | 双边 0.1%（2021-08-01 至 2023-11-16 为 0.13%） | 交易费 0.00565%、证监会征费 0.0027%、会财局征费 0.00015% |

### 6. 引擎输出与诚实检查（`packages/engine`）

```ts
simulate(input: SimInput): SimResult   // 纯函数；回测和跟踪共用
interface SimResult {
  series: { date: string; nav: number; bench: number; cash: number; positions: number }[];
  trades: { date: string; code: string; side: 'buy' | 'sell'; price: number; shares: number;
            fee: number; reason: 'rebalance' | 'take_profit' | 'stop_loss' | 'max_hold'
                   | 'filtered' | 'signal' }[];
  holdings: { date: string; items: { code: string; weight: number }[] }[];   // 每个调仓日一份
  metrics: Metrics;     // 总收益、年化、超额（累计/年化）、最大回撤及区间、波动、夏普(rf=0)、
                        // 卡玛、胜率、平均持有天数、年换手、费用拖累、交易次数、月度/年度收益、
                        // 样本内/样本外分段指标
  attribution: { byStock: …; byIndustry: …; industryExposure: … };
  checks: Check[];
}
```

诚实检查（`checks`，阈值集中定义在 `engine/checks.ts`）：

| id | 触发条件 | 级别 |
|---|---|---|
| `oos_decay` | 样本外年化超额 < 样本内的 50%，或方向相反 | warn |
| `few_trades` | 买入笔数 < 30 | warn |
| `concentration` | 盈利前 2 只贡献 > 总盈利 50%，或单一行业平均权重 > 40% | warn |
| `tuning_count` | 同一策略在同一区间已回测 ≥ 10 个版本 | info → ≥ 20 升为 warn |
| `cost_drag` | 费用 > 毛超额的 20% | info |
| `survivorship` | 该市场的数据仓没有退市股（由探针结论决定） | warn，常驻 |
| `bench_no_div` | 基准是价格指数、不含分红 | info，常驻 |

参数敏感度（`sensitivity` 任务）：对一个参数扫描 ≤ 8 个取值，逐个回测后给出曲线；
如果相邻取值之间年化超额的波动超过阈值，就标记为「参数脆弱」。

### 7. 向前跟踪

- 上线：用户在卡片或页面上确认 → 生成 `Tracking { strategyVersionId, startDate = 下一个交易日, capital }`。
  版本固定；策略改了要重新上线，新跟踪和旧跟踪并存，旧的可以停掉。
- 结算：每晚 ETL 完成后，对每个运行中的跟踪用 `simulate` **从起点重放到最新交易日**，
  结果写入 `tracking_days`。和回测同一段代码，规则只改一处。跟踪天数不多，重放的成本可以忽略。
- 今日信号：重放结束时引擎给出「下一个交易日计划买卖」，写入 `tracking_orders`。
- 与回测对照：取该版本在上线日前最近一次回测，
  计算「跟踪期累计超额在回测所有等长窗口中的百分位」。例如「跟踪 40 天超额 −3.2%，处于回测同长度窗口的第 18 百分位」。
  这是确定性算出来的，看板和简报都用这个数。
- 信号模式的策略 v1 只能回测，不能上线。

### 8. 调度（worker，显式 `Asia/Shanghai`，不依赖系统时区）

| 时间（工作日） | 任务 |
|---|---|
| 17:30 | A 股：判断今天是否交易日（今天的指数日线存在）→ 日线/估值/财报公告增量 → 因子 → 数据版本 +1 → A 股跟踪结算 |
| 18:00 | 港股：同上 |
| 19:00 | 简报：给每个有运行中跟踪的用户生成一份 |
| 每周日 03:00 | 全量校验：抽样比对历史日线，记录 `revised_rows` |

任何一步失败都写入 `jobs` 并中止后续步骤。看板顶部显示「数据截至 X，最近一次更新失败」横幅，
管理页可以看到失败原因并手动重跑。

**简报**：worker 先算出确定性的 `briefFacts` JSON，包括各跟踪的当日收益、累计超额、偏离百分位、
新信号、新增检查项。LLM 只基于这份 JSON 写 ≤ 150 字的口语化摘要，facts 和正文一起存档。
简报不计入用户的对话额度，单独统计系统用量。（简报的保留已由 [20261005-vt-borrowing.md](20261005-vt-borrowing.md) D70 修订：
每一版都保留，不再按天数清理。）

### 9. 对话 Agent（`apps/server/src/agent`）

- `streamText` + tools，`stopWhen: stepCountIs(8)`；会话和消息（AI SDK UI message parts）持久化。
- 会话绑定页面上下文 `{ strategyId?, runId?, trackingId? }`，system prompt 会带上当前上下文的摘要。
- **工具输出分两份**：UI 拿完整 payload 渲染卡片，模型通过 `toModelOutput` 只拿精简摘要。
  system prompt 规定：回复里的数字必须来自工具输出，并引导用户看卡片。

| 工具 | 作用 | 卡片 | 写库 |
|---|---|---|---|
| `list_factors` | 按市场列出可用因子及口径 | — | 否 |
| `get_strategy` | 读取策略及其当前版本 | 策略卡 | 否 |
| `propose_strategy` | 新建或修改（完整 spec 或 JSON Patch）；服务端 zod 校验，不合法就把错误返回给模型让它改 | **Diff 卡（确认/放弃）** | 只写 draft |
| `run_backtest` | 对某个版本发起回测 | 进度卡 → 结果卡 | 写 run |
| `get_run` | 指标 + 检查项 | 指标卡 + 曲线 | 否 |
| `query_run` | 下钻：回撤区间 / 某日持仓 / 交易明细 / 贡献排名 / 行业暴露 / 月度收益 | 表格或图 | 否 |
| `compare_runs` | 2–4 个 run 对比 | 对比卡 | 否 |
| `run_sensitivity` | 单参数扫描（≤ 8 个取值） | 扫描卡 | 写 run |
| `screen_today` | 按某个版本在最新数据日选股 | 表格 | 否 |
| `lookup_security` | 按名称或代码查个股的因子卡 | 个股卡 | 否 |
| `propose_tracking` | 提议上线跟踪 | **确认卡** | 只写 draft |

- **LLM 不能直接改持久状态**：策略版本和跟踪只能通过用户点击卡片上的确认按钮生成
  （`POST /api/drafts/:id/confirm`，只接受当前会话用户的 cookie）。回测和扫描不会破坏任何数据，可以直接执行，但受额度和队列限制。
- **图表可以直接提问**：回测报告和看板的净值图支持框选区间，点「问 AI」后，
  上下文 `{ runId, from, to }` 会带进对话，并自动触发 `query_run`。
- **模型配置**（实例级 `.env`）：`LLM_PROVIDER=openai-compatible|anthropic`、`LLM_BASE_URL`、
  `LLM_API_KEY`、`LLM_MODEL`、`LLM_MODEL_BRIEF`（可选，更便宜的模型）。默认 OpenAI 兼容协议接 DeepSeek。

- better-auth（email + password）。**空库时第一个注册的人自动成为管理员**。

## 验收标准

1. **点时正确**：单测覆盖以下三点。某只股票某期财报 `notice_date = D`，D 的前一个交易日因子里不含这期数据，D 起含；
   ST 按当日简称判定；A 股已退市股票在上市期间出现在股票池里（前提是探针确认能拿到退市股）。
2. **引擎正确**：手算夹具（3 只股票、20 个交易日，覆盖涨停买不进、停牌顺延、分红、止损、整手、最低佣金）
   下，逐笔成交和每日净值与期望值一致到分。
3. **性能**：在线上服务器上，全 A 股 2016-01 至今、月度调仓、top 20 的回测 ≤ 30 秒，worker 峰值 RSS ≤ 1 GB。
4. **可复现**：同一版本 + 同一数据版本重复回测，metrics 和 trades 完全一致；
   跟踪每天重放的结果和已存的历史天数据一致。
5. **对话闭环**：在对话里说「建一个 A 股 PE<20、ROE>15%、月度调仓的策略并回测」，依次出现 Diff 卡 →
   点确认 → 进度卡 → 结果卡；再说「止损改成 10% 再跑一次并对比」，出现对比卡。
   抽检 20 条回复，没有一条出现卡片之外的数字。
6. **LLM 不能越权**：API 测试证明，不经过 `drafts/:id/confirm`，任何工具调用都产生不了策略版本或跟踪。
7. **看板**：有 ≥ 1 个运行中的跟踪时，首页的简报、跟踪榜、回测段 + 跟踪段曲线、今日信号齐全，
   「数据截至」与最新数据版本一致；手动让 ETL 失败后，首页出现横幅。
8. **账号与港股**：空库时第一个注册者成为管理员；没有邀请码的注册被拒绝；超额请求返回 429 和提示。
   一个港股策略（恒指基准）能走完回测和跟踪全流程，港股不可用的因子在编辑器和 `list_factors` 里都选不到。

## 决策记录

- **D1 全 TS monorepo，沿用作者其他项目的栈（Hono + Vite React + Drizzle + pm2）。**
  理由：用户要求全仓 TS；这套栈已在同一台服务器上跑过两个站点。
  放弃的方案：Next.js（不需要 SSR，而且 `next build` 在 3.6 GB 的机器上吃紧）；Python 引擎（违背全 TS 的要求，
  代价是没有 pandas，引擎要自己基于 TypedArray 写，但逻辑本身不复杂）。
- **D2 应用库用 SQLite，行情仓用 DuckDB 文件。** 理由：自部署零外部服务；横截面因子查询 DuckDB 快一个数量级。
  放弃的方案：Postgres（多一个服务要部署）；全部放 SQLite（全市场横截面计算太慢）；Parquet 快照目录（多版本管理 v1 用不上）。
- **D3 server 和 worker 两个进程，worker 独占 DuckDB，回测在 worker_threads 里跑。**
  理由：ETL 和回测的内存尖峰不应拖垮 API；DuckDB 不支持多进程同时读写同一个文件。
  放弃的方案：单进程（隔离差）；Redis 队列（多一个依赖，SQLite `jobs` 表够用）。
- **D4 策略是结构化 DSL + 因子白名单，LLM 只能产生草稿，用户确认后才成为版本。**
  理由：可校验、可复现、可编译成 SQL，没有代码执行面。放弃的方案：让 LLM 写策略代码（无法校验，
  有安全风险，也不可复现）。
- **D5 回测只支持规则策略和信号导入；AI 判断型策略不做。** 理由：LLM 的训练数据泄漏未来。
  二期再考虑「只能向前跟踪」的 AI 策略。
- **D6 T 日收盘决策、T+1 开盘价成交（不复权价 + 整手），收益按后复权计。**
  理由：用当天收盘的数据做决策，又按当天收盘价成交，结果偏乐观；前复权价会随未来的分红漂移，结果不可复现。
  放弃的方案：T 日收盘价成交（Iva 用的口径）。
- **D7 基准：A 股默认沪深300，港股默认恒指；优先用全收益指数。** 如果探针找不到可用的全收益数据源，
  就用价格指数，并常驻 `bench_no_div` 提示（策略含分红，基准不含，比较会偏向策略）。
- **D8 因子物化到 `factors_daily`，带 `registry_version`，因子定义变了就全量重算。**
  理由：5 年分位这类滚动计算放到回测时现算太慢。放弃的方案：回测时现算。
- **D9 数据源走 `MarketDataSource` 接口，v1 实现东财 + 腾讯。** Tushare 二期按同一接口接入，
  上层代码不感知数据来自哪里。（已由 [20261005-vt-borrowing.md](20261005-vt-borrowing.md) D72 修订：按能力分的回退链与来源记录。）
- **D10 LLM 用 AI SDK 的多 provider 方案，默认 OpenAI 兼容协议接 DeepSeek；实例统一 key，每用户每日额度。**
  （用户已定）理由：线上服务器在国内网络环境，直接连不上 Anthropic 和 OpenAI；开源用户可以自己换 provider。
- **D11 邀请码注册，空库时首个用户为管理员，用 better-auth。**（用户已定）放弃的方案：开放注册；只允许管理员建号。
- **D12 一个策略只选一个市场。**（用户已定）理由：不用处理汇率和港股通规则，基准也清楚。
- **D13 向前跟踪和夜间简报放进首版；跟踪每天从起点重放，和回测用同一个 `simulate`。**（范围由用户定）
  理由：回测和跟踪的规则只在一处实现，不会漂移。放弃的方案：每日增量推进持久化状态。
- **D14 日期一律存交易所本地日期字符串，调度器显式使用 `Asia/Shanghai`。**
  理由：避免机器时区导致日期错位（Iva 就吃过东京时区让日期早一天的亏）。
- **D15 两次调仓之间卖出得到的现金闲置到下一个调仓日。** 理由：这样选股不依赖持仓状态，
  可以两阶段计算来控制内存，语义也简单。放弃的方案：卖出后立即补位（二期可以做成选项）。
- **D16 工具输出分两份：UI 拿完整 payload，模型拿精简摘要。** 理由：数字以卡片为准，同时省 token。
- **D17 界面只做中文，文案集中管理。** 英文界面等公开发布前再加。

以下 D18–D26 是 Phase 0 数据探针（2026-09-28，`docs/probe-report.md`，本机与线上服务器均实测可达）之后追加的。

- **D18 数据从 2013-01-01 起回填，回测默认起点 2018-01-01。** 理由：`pe_pct_5y` 需要 5 年历史；
  2013 起回填让 2018 年以后的分位完整。允许更早的起点，但分位类因子至少要 3 年样本，不足时为空。
  修正 §3.2 的「2016 起回填」。
- **D19 A 股、港股估值全部自算，不用东财估值表。** 市值 = 不复权收盘 × 当日有效总股本
  （东财股本变动 `RPT_F10_EH_EQUITY` / `RPT_HKF10_INFO_EQUITY`，带生效日，覆盖退市股）；
  PE_TTM = 市值 / TTM 归母净利，PB = 市值 / 归母净资产，财报按公告日生效。
  理由：东财估值表 `RPT_VALUEANALYSIS_DET` 只到 2018 年且不含退市股（幸存者偏差）。它只在体检里做抽样核对。
  因此 §3.2 的 `valuation_daily` 是自算结果，不再「取源数据」。
- **D20 A 股股票池 = 东财公司资料（含退市，给上市日、三级行业）+ 交易所官方退市名单（给退市日）。**
  深交所 208 家、上交所 146 家，2013 年后退市 274 家，全部纳入。财报必须逐股取主要指标
  （`RPT_F10_FINANCE_MAINFINADATA`），因为全市场业绩报表 `RPT_LICO_FN_CPD` 不含退市股。
  **北交所 v1 不回填、DSL 不提供 `bse` 板块**（本来就默认不纳入，省掉回填量）。
- **D21 ST 点时判定分三档，并在结果里标注近似。** 深市：深交所官方简称变更（7483 条，含日期），精确；
  沪市 2018 年起：东财每日估值表里的当日简称（在市股票）；沪市 2018 年前与沪市退市股：找不到公开的
  简称历史，用「最近两期年报归母净利均为负」近似，回测检查项加 `st_approx`（info）。
  放弃的方案：只用当前简称（会把现在是 ST 的股票在整个历史里都排除，是未来函数）。
- **D22 港股财报生效日按法定披露期限保守推算。** 东财港股财报没有公告日字段；年报 = 报告期末 + 90 天，
  中报与季报 = 报告期末 + 60 天。可能晚于真实公告日（偏保守，不会偷看未来）。
- **D23 港股财报金额按记账币种换港币。** 探针实测 2025 年报：人民币 1322 家、港币 730、美元 101，
  另有新元、马币等 8 种。汇率用中国外汇交易中心人民币中间价（覆盖以上全部币种），
  按「金额 × 外币/人民币 ÷ 港币/人民币」换算。股息率由复权因子跳变推导：
  除权日现金分红 ≈ 前收 × (1 − (1 + 送转比例) / 因子跳变倍数)，送转比例来自同期股本变动。A 股、港股同一套算法，不另抓分红表。
- **D24 基准都用含分红口径（D7 落地）。** A 股默认 `csi300` = 中证官网 H00300 沪深300全收益；
  港股默认 `hsi` = 盈富基金 02800 后复权价（恒指含分红代理，含约 0.1%/年管理费）；`hscei` = 02828 后复权。
  `sse`（上证价格指数）保留作可选，选它时常驻 `bench_no_div`。H00300 通常晚 1 个交易日发布：
  夜间结算时最新一两天用沪深300价格指数涨跌临时补齐并标记 provisional，下一次 ETL 覆盖。
  跟踪每天从起点重放（D13），所以会自动修正。
- **D25 港股回测有幸存者偏差，常驻 `survivorship` 提示。** 找不到港股退市名单的免费接口，
  而且港股代码退市后会被重新分配，不能用「代码没行情了」来推断退市。
- **D26 抓取节奏：每个域名并发 4、请求间隔 ≥ 50ms（约 20 次/秒）。** 实测腾讯平均 61ms、东财 116ms，无失败。
  全量回填约 12 万次日线请求 + 2.4 万次东财请求，约 2 小时，按 `etl_progress` 断点续跑。
  线上服务器实测空闲内存约 1.2 GB：DuckDB 默认 `memory_limit=512MB`，回测线程池默认 1。

以下 D27–D30 是 Phase 1 实施中（2026-09-28）追加的。

- **D27 日线主数据源改为东财 `push2his`，腾讯作为后备（修正 D9 的实现分工）。** 小规模回填时，本机 IP 在几百次请求后
  就被腾讯 `fqkline` 的 WAF 封禁（返回 HTTP 501 拦截页，持续 5 分钟以上）；线上服务器当时仍可访问。
  东财 `push2his.eastmoney.com`（注意不是 `push2`）一次请求返回整段历史，带成交额，本机和线上服务器都能连。
  这样回填的日线请求从约 12 万次降到约 1.7 万次。指数也改走东财（1.000300、100.HSI 等）。
  HTTP 层识别到风控页后，这个域名暂停 5 分钟起、翻倍到最长 1 小时，调用方改用另一家数据源。
  腾讯的节奏降到每秒 4 次，东财日 K 每秒 10 次。
- **D28 复权因子自算：从后复权价反推公司行动（修正 D23 的分红推导）。** 实测腾讯和东财的「后复权」
  都是 `a × 不复权价 + b`（加法复权，送转时 a 变），不是等比复权。直接拿比值当因子会把分红当成
  不再投资的现金，茅台 2013 年以来的收益会少算约 14%。
  `compute/adjust.ts` 用日内合并回归求 a，识别送转（原价相对后复权价跳 ≥ 8%，或斜率显著变化，
  如东财把腾讯 2022 年派京东股份按比例调整，a 只变了 3%），再对 b 做阶跃检测找除息日。
  结果写入 `corp_actions`（每股现金、送转比例），等比因子 `bars_daily.adj` 表示分红再投入；
  股息率与股本对齐都改用这张表。已用茅台、平安、工行、包钢、宁德、腾讯、汇丰、中移动、
  平安 H 等 10 只股票的 14 年历史核对，派息、送转、特别股息、实物分派都能对上。
- **D29 港股主要指标的金额币种要逐期判定（补充 D23）。** 东财港股主要指标对人民币记账的公司保留人民币
  （腾讯、建行），对美元记账的公司已换成港币（汇丰）。判定方法：拿利润表里「股东应占溢利」的原币金额
  与主要指标的归母净利比，比值约等于 1 就是记账币种，否则是港币。修正后，汇丰和腾讯的 PE 与市值都能自洽。
- **D30 自算估值与东财估值表核对通过。** 2024-06-28 抽样平安银行、宁德、工行、茅台、包钢：
  市值和 PE_TTM 与东财一致到 0.01；PB 除宁德（3.62 对 3.81，净资产口径不同）外一致。
  因子表另加了 `turnover_20d`（20 日均成交额，用来排除流动性差的股票），成交额取自东财日 K。

以下 D31–D35 是 Phase 1–4 实施中（2026-09-28 晚）追加的。

- **D31 所有数据源都要慢、串行，被封能自愈（修正 D26 的节奏）。** 东财 `push2his` 在并发 4、约每秒 10 次时，
  一两百次请求后本机 IP 被重置连接，封了数小时；深交所连续拉几百页简称变更后也被拒。现在的做法：
  - 日 K 接口串行，间隔 0.6 秒起；交易所与官方站点间隔 0.3 秒；东财数据中心间隔 0.1 秒；都加 0–50% 随机抖动。
  - 连续 6 次连接级失败也视为被封（东财被封时表现为空响应，不是拦截页）。
  - 回填遇到两家日 K 都被封时原地等待解封，不把这只股票记为失败。
  - **A 股日线改成一只股票一次请求**：东财不复权日 K 的「涨跌额」是相对交易所参考前收算的，
    参考前收 = 收盘 − 涨跌额。平常它等于昨收，除权除息日它就是除权参考价，二者之比正好是等比因子的跳变
    （`adjFromRefPrices`）。现金与送转比例的拆分挪到算因子时，结合股本变动完成（`resolveActions`）。
    港股报价不做除权调整，仍用「不复权 + 后复权」反推（D28）。
  - 开发机被东财封禁期间，用 `KLINE_SOURCE=tencent` 只走腾讯，用 `--top N` 只回填市值最大的 N 只。
- **D32 调仓带缓冲，卖出后现金闲置（D15 落地细节）。** 调仓日卖出掉出前 ⌈top × buffer⌉ 名的持仓（DSL `rebalance.buffer`，
  默认 1.5，1 = 严格前 top 名）；空位按名单顺序补足，每只预算 = min(上一收盘总资产 / top, 现金 / 空位数, 单只上限)，
  已有持仓不做再平衡。决策日停牌的持仓不因「掉出名单」卖出。放弃的方案：每次调仓都等权再平衡（换手高，与 Iva 的持有逻辑也不一致）。
- **D33 持仓按「分红再投入」计价，止盈止损按含分红涨跌判断，不含费用。** 持仓价值 = 买入股数 × 收盘价 × 当日因子 / 买入日因子，
  卖出时股数按同样比例折算，允许小数。放弃的方案：分红记为现金。那样现金要闲置到下次调仓（D15），会系统性低估收益。
- **D34 信号模式：信号日收盘后决策、下一个交易日开盘买入，最多同时持有 `signals.maxPositions` 只。** 卖出只靠 exits。
  这就是 Iva A/B/C 组合那类「推荐池 + 仓位规则」的回测方式。
- **D35 对话工具在 spec §9 的 11 个之外，加了 3 个只读工具：`list_strategies`、`list_runs`、`get_tracking`。**
  用户说「上个版本」「那个高股息策略」时，模型要先能查到 id。这 3 个都只读，不改变 D4 的「只写草稿」约束。
  `run_backtest` / `run_sensitivity` 用异步生成器先吐出 runId，卡片立刻显示进度，模型拿到的是跑完后的摘要。

以下 D36–D39 是收尾自查与端到端验证（2026-09-28 晚）时追加的。

- **D36 夜间增量只有「核心步骤」失败才中止（细化 §8 的「任何一步失败都中止后续步骤」）。**（已由 [20261005-vt-borrowing.md](20261005-vt-borrowing.md) D73 修订：完整性闸门与自动重跑。）
  核心步骤 = 日历、日线、因子、数据版本：任何一个失败，任务失败、不结算跟踪，看板出横幅，简报开头说明
  「某市场今天数据没更新成功，下面还是 X 日的结果」。汇率、证券表刷新、简称、财报/股本增量这些辅助步骤失败时，
  记日志、沿用旧数据，继续往下走。理由：D31 之后东财数据中心和交易所站点偶尔封 IP 几十分钟到几小时，
  如果辅助接口一抽风就中止，跟踪结算和简报会整晚停摆；而辅助数据晚一天影响很小（下次增量会补，因子每天重算近 15 天）。
  放弃的方案：全部硬失败（一个辅助接口抽风，整晚没有结果）；全部软失败（日线没更新却生成新数据版本，跟踪会用旧价格结算）。
- **D37 跟踪结算先比对再改写，简报用量单独记账（落实验收 4 与 §8、§10）。** 每次重放前读出已存的 `tracking_days`，
  和新结果逐日比净值与基准（`compareReplay`）。同一版本 + 同一数据，结果应当完全一致，引擎单测覆盖「数据每多一天，
  之前每一天都不变」。不一致只可能来自数据修订，照常改写，但把天数和最早日期记进 `trackings.summary.replay`，
  跟踪页显示一行说明。夜间简报的 token 记在 `usage_daily` 的 `user_id = 'system'` 上，不占任何人的额度；
  管理页新增近 14 天的 LLM 用量表，分开显示对话和简报。
- **D38 夜间增量不写盘中价，也不把「日 K 晚到」当休市。** 两种情况原来都会悄悄出错：
  - 收盘价定稿前（北京时间 A 股 15:30、港股 16:30 之前）抓日线，会把盘中价当收盘价写进库；之后的增量又会跳过
    已有当天 K 线的股票，错价就一直留着。现在夜间增量在这之前直接报错；回填自动只取到昨天。
  - 日历指数的日 K 里没有今天，原来直接判为休市、任务成功结束，看板不出横幅。现在先用腾讯指数实时报价交叉验证：
    报价日期是今天，说明开市了、只是日 K 晚到，这时让任务失败，等管理页重跑。
  - 顺带：夜间报价路径改为写入真实成交额（A 股报价第 35 段「价/手/元」、港股第 37 段），不再留空后用收盘 × 成交量近似。
- **D39 夜间增量、财报增量、每周抽检只维护「库里已有日线」的股票。** 用 `--top` 回填的库，第一次夜间增量会把
  其余几千只股票当成「缺数据」，悄悄从上市日起补全历史（港股财报增量实测一跑就是全市场 2900 只）。现在只有库里已有日线的股票、
  以及近 30 天上市的新股会被增量维护；要扩大范围就再跑一次回填。放弃的方案：夜间顺手补全（耗时不可控，还会被封 IP）。

以下 D47–D50 是 2026-09-29 按 Jim「把 A 股价值组合加进 Ivan」追加的（研究过程见落地记录）。

- **D47 因子注册表第 2 版：新增 ROE 三年最低、派息率、近三年分红年数、PEG、12-1 月动量、全市场市值排名。**
  - 口径：
    - ROE 三年最低：当前、约 250、约 500 个交易日前三个时点的 ROE（TTM）取最低，缺的时点跳过。
    - 派息率：股息率 × 市盈率，%。
    - 近三年分红年数：同样三个时点里「近 12 个月有现金分红」的个数，0–3。
    - PEG：市盈率 ÷ 净利两年复合，两者为正才有值。
    - 12-1 月动量：第 250 到第 20 个交易日前的后复权涨幅。
    - 全市场市值排名：见 D49。
  - 为什么选这几个：研究时补全了「当时」的股票池，每月按单个指标分五组，看之后 12 个月的收益，2018–2025 年分前后两段都看。
    - 稳定有效：现金流 / 净利（八成以上月份有效）、离一年高点的距离、动量。
    - 便宜类（行业内的市盈率 / 市净率 / 股息率）只在 2022 年后有效。
    - 高 ROE、高增长、PE 5 年分位、F 分都无效，或者有害。
    - 所以新因子都是拿来做「门槛」和「排雷」：「三年都赚钱」筛掉周期顶点的一年暴利；派息率筛掉分得比赚得多的。
  - 实现上的约束：新因子只能加在注册表末尾。已有行情仓打开时，表结构第 2 版用 `ALTER TABLE … ADD COLUMN IF NOT EXISTS` 在表尾补列，
    列顺序必须和注册表一致，否则追加写入会错列；有单测守着。注册表版本号加 1 后，下一次夜间更新全量重算因子。
  - 放弃的方案：
    - 另加 EP、BP 因子：市盈率、市净率选「越低越好」排出来是同一个顺序。
    - F 分、总资产增速：在这个股票池里没有效果。
- **D48 排序项可以「行业内比较」，策略可以限「同一行业最多 N 只」。**
  - DSL：`rank.terms[].neutral`（该项的百分位只在同日同一一级行业里算）、`rank.maxPerIndustry`（先在行业内按得分截断，再取全市场前 N）。
  - 为什么要：全市场比便宜，最便宜的永远是银行、地产、建筑，等于押行业；行业内比，稳定性明显更好（IR 0.43 → 0.74）。
    行业上限主要降集中度，最差年份更浅。
  - 按一级行业，不按二级：二级行业在 800 只里平均一组只有几只，百分位太碎。
  - 编辑器里每个排序项多一个「行业内比」勾选，排序区多一个「同一行业最多 N 只」。人话描述、版本差异、AI 的 DSL 说明都同步更新。
- **D49 「当时市值前 N」的股票池 = 条件 `mcap_rank ≤ N`。**
  - 市值排名在因子物化的横截面 SQL 里算（同日同市场），和行业市值排名一样。
  - 为什么要：只用今天的大公司回测，等于提前知道了谁后来会变大、谁没倒。研究里这一项让回测虚高很多：
    港股高股息年超额 16% → 7%，低估值高ROE 从 +5.9% 变成 −8.5%。
  - 前提是行情仓回填了全市场。只回填了部分股票时，排名只在已回填的股票里排，会偏高；因子说明里写明了。
    线上靠全量回填（`scripts/backfill-full.sh`）。
  - 放弃的方案：
    - 单独存东财的历史市值排名快照：多一个数据源要维护，而且只有 2018 年以后才有。
    - DSL 里加 `universe.topN`：用现成的条件就够了，AI 和编辑器都不用学新写法。
- **D50 「价值组合」三个模板：质量价值（40%）、红利价值（30%）、合理价格成长（30%），组合比例由用户自己分配资金。**
  - 三条的共同纪律：
    - 排除 ST、次新股、亏损股；20 日均成交 ≥ 0.5 亿；不接飞刀（250 日跌幅不超过 30%）。
    - 每季第一个交易日调仓，缓冲 2 倍；同一行业最多 3 只；等权；不止损。
    - 不止损的理由：研究里止损在各类策略中几乎全是减分。
  - 各自的规则：
    - 质量价值：市值前 800；ROE 三年最低 ≥ 5%、现金流 / 净利 ≥ 0.5；按行业内的市盈率 / 市净率 / 股息率 ×1、行业内的现金流 / 净利 ×3、
      距一年高点与 12-1 月动量各 ×1.5 排序；持 30 只。
    - 红利价值：市值前 300；股息率 ≥ 2%、派息率 ≤ 80%、近三年至少两年分红、现金流 / 净利 ≥ 0.5、市盈率 ≤ 20；
      按股息率 ×3 + 行业内现金流 ×1 + 强度 ×0.75 排序；持 20 只。
    - 合理价格成长：市值前 800；营收、净利两年复合 ≥ 10%，PEG ≤ 1.5，ROE ≥ 10% 且三年最低 ≥ 10%，现金流 / 净利 ≥ 0.5。
      增长只做门槛，排序同质量价值；持 30 只。
  - 回测：应用自己的代码和行情仓，2018-01-02 至 2026-09-28，100 万，同期沪深300 全收益年化 3.1%、最大回撤 −42%。
    - 质量价值：年化 10.7%、年超额 +7.3%、最大回撤 −31%。
    - 红利价值：年化 8.3%、年超额 +5.0%、最大回撤 −27%。
    - 合理价格成长：年化 11.4%、年超额 +8.1%、最大回撤 −34%。
    - 按 40/30/30、每季再平衡合在一起：年化 10.5%、年超额 +7.2%、最大回撤 −27%，9 年里 8 年跑赢。
  - 期望要打折：参数在合理范围内随机换 30 组，三条全部跑赢基准，但年超额中位约 5–7 个点，比模板这组低。
    因子是看过这 8 年数据后挑的，属于样本内。
  - 放弃的方案：
    - 做成一个「组合」对象、统一跟踪：先用三个模板 + 首页多策略对照图，看用户怎么用再说。
    - 给「价值」加绝对市盈率上限（≤ 30）：这几年每年少 1–3 个点，好机会常在「行业里便宜、绝对值不低」的公司。
    - 3–6 个月的短周期单独出一套：研究里和把这个组合改成每月调仓打平，没必要。

- **D51 A 股成交量一律存成「股」。科创板在腾讯接口里本来就是「股」，旧代码多乘了 100。**
  - 2026-09-29 实测：腾讯日 K 和实时报价里，主板、创业板、北交所的单位是「手」，科创板（688/689）是「股」。
    东财当时从本机和服务器都连不上，没有实测。
  - 做法：
    - 有成交额时（东财日 K、实时报价）不看来源口径，按「成交额 ÷（价格 × 成交量）」判断单位：约 100 是手，约 1 是股。
    - 没有成交额时（腾讯日 K）按板块判断。
    - 代码在 `compute/volume-unit.ts`，有单测。
  - 已入库的数据修正一次，靠行情仓 meta 键 `fix:a_volume_units_2026_09` 保证只跑一次：
    - 有成交额的行，比值 < 0.05 的除以 100；
    - 没有成交额的科创板行一律除以 100，因为旧代码写入的腾讯日 K 全都被放大了。
    - 这条不是幂等的，所以放在只跑一次的 `DATA_FIXES` 里，不放在每次升表结构都会整体重跑的 `SCHEMA_SQL` 里。
  - 放弃的方案：按「换手率高得离谱」判断。中芯国际这类 A+H 总股本很大的公司，放大后的换手率也不离谱，判断不出来。
  - 影响：科创板的 20 日均成交额原来虚高 100 倍，流动性条件拦不住它们；量比不受影响。

以下 D52–D54 是 2026-09-29 按 Jim「加仓位控制（按波动）、按大盘状态切换选股做成模拟跟踪实验」追加的。

- **D52 仓位控制：按波动控制仓位（`exposure.volTarget`，可选，默认不开）。**
  - 规则：
    - 每周最后一个交易日收盘，算当前持仓组合近 60 个交易日的年化波动：按市值加权、含分红，再乘上「满仓时股票占总资产的比例」。
    - 仓位系数 = 目标波动 ÷ 实际波动，按 10% 向下取整，最多 1。系数变化 ≥ 10% 才动。
    - 下一交易日开盘，把每只老持仓按同一比例增减，当天新买的不动；新买入的预算也乘这个系数。
    - 停牌、涨跌停开盘的那只当天不调。空出来的钱不计利息，偏保守。
  - 为什么用「当前持仓的波动」，而不是「策略自己净值的波动」：后者依赖历史净值，跟踪从上线日才有净值，
    头几个月算不出来，和回测对不上。持仓的波动从第一天就能算，回测和跟踪完全同一套逻辑。
  - 研究结论：
    - 在长期组合上，这是唯一「几乎不花钱」的仓位规则：收益基本不变，回撤少 3–4 个点，夏普略升。
    - 趋势类「跌破均线减半」是有代价的保险（每年少赚 1.2–2.6 个点），这次没做。
    - 应用回测：三条价值策略都开 18% 时，组合年化 10.5% → 10.1%、回撤 −27% → −25%、夏普 0.66 → 0.71。
  - 记录与展示：
    - 交易原因新增「仓位控制」；指标新增「平均股票仓位」（所有策略都有）；引擎版本 1.0.0 → 1.1.0。
    - 跟踪的摘要里记当前系数和下一个交易日要调到的系数，跟踪页显示在「总资产」下面。
    - 持仓的盈亏归因改用剩余持仓成本：减仓时按比例扣成本，加仓时加上成本。
    - 为了开头就能算波动，开了仓位控制时，回测会多装约 3 个月的历史价格。
  - 放弃的方案：
    - 每天评估：调得太勤，费用高，研究里全面更差。
    - 对整个组合按总仓位「再平衡」：会把因为空位留下的现金也买满，改变了策略原来的行为。
- **D53 按大盘状态切换排序（`rank.regime`，实验）。**
  - 规则：决策日沪深300（港股用恒指）的收盘价在 N 日均线（默认 200）下方时，改用 `regime.weak.terms` 排序，上方时用原来的 `terms`。
    - 指数用不含分红的价格指数，只用决策日及以前的数据；决策日指数没数据就用之前最近一个交易日。
  - 回测时强势日、弱势日分开跑选股 SQL。「今日选股」会注明当天用的是哪一套。
    报告的检查项里写明共多少次调仓、其中几次用了弱势排序。
  - 为什么是实验：研究里强势期「股价强度、业绩增长」有效，弱势期「便宜、现金流、低波动」有效。
    按大盘状态切换权重，30 组参数里 25 组提高了收益，但只有约一半在前后两段都提高。
    所以做成一个开关加一个实验模板，先模拟跟踪，和原版对照。
  - 编辑器：勾选「大盘走弱时换一组排序（实验）」后，出现均线天数和第二组排序项（复用同一套排序项编辑行）。
- **D54 实验模板「价值组合·质量价值（大势切换·实验）」。**
  - 在质量价值的基础上加 D53：
    - 强势期：强度（距一年高点、12-1 月动量）各 ×3，归母净利同比 ×1.5，现金流 ×3，便宜三项各 ×0.5。
    - 弱势期：便宜三项各 ×2，现金流 ×4.5，60 日波动越低越好 ×1.5。
  - 应用回测（2018-01-02 至 2026-09-28，100 万）：年化 12.6%（原版 10.7%），年超额 +9.2%（原版 +7.3%），
    最大回撤 −27%（原版 −31%）。35 次调仓里有 16 次用了弱势排序。
  - 这是在同一段数据上挑出来的，看的是它往后的模拟跟踪能不能继续比原版好；原版和实验版一起跟踪。

## 风险

| 风险 | 缓解 |
|---|---|
| 东财/腾讯非官方接口变动或限流 | adapter 隔离；`pnpm ivan doctor` 逐个探测接口；缓存 + 退避；Tushare 作为二期备选 |

| 首次回填耗时长 | 可断点续跑；预估时间写进 README；线上服务器上一次性跑完 |
| DeepSeek 工具调用不够稳 | zod 错误信息写清楚、prompt 里给示例；provider 可切换 |
| 开源项目抓取第三方接口的合规问题 | 用户自己部署、自己运行；README 免责声明；限速礼貌抓取 |
